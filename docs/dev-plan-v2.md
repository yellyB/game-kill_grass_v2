# 풀죽이기 v2 — 세부 개발 계획 (실행 로드맵)

> 상태: 기획 확정(freeze 직전). 이 문서는 실제 구현 착수용 세부 실행 계획.
> 상위 기획·설계 확정 내용은 `docs/pc-port-plan.md`, 밸런스 수치는 `sim/balance_sim.py` 참조.
> 원본(이식 대상) 코드: `../game-kill_grass` 및 git `HEAD 4cd58ca`.

## 전역 원칙 (에셋·UI·스타일)

- **그래픽·사운드는 기본적으로 원본 게임 것을 그대로 사용.** (별도 신규 에셋은 명시적으로 필요할 때만)
- **텍스트 스타일·간격·폰트 등 스타일링도 원본 방식 유지.**
- **UI·스타일·레이아웃 관련은 별도 언급이 없으면 기존(원본) 방식 유지.** 변경은 이 문서/지시에서 명시된 것만.
- (연계) UI 전역 원칙: 텍스트 지양, 아이콘/색상 우선, 원본에 없던 신규 문자열 금지(번역량 절감).

## 아키텍처 결정 (확정)

**A안 — 공통 `core/` (SSOT).** 밸런스 수치·공식을 GDScript 순수 로직 레이어(`core/`) 한 곳에 두고,
**게임과 헤드리스 시뮬이 같은 코드를 호출**한다. 파이썬 `balance_sim.py`처럼 로직을 별도 복제하는 방식은 drift 위험이 있어 지양(pc-port-plan §9.1).

- **핵심 규칙:** `core/`에는 화면/노드/입력 코드 금지 — 순수 함수만(Godot Node 의존 0).
  이 규칙이 "공유 편의"와 "미래 분리 용이"를 동시에 보장한다(core/는 아무것도 의존하지 않는 잎 모듈).
- 관계: `게임 → core/ ← 시뮬` (단방향). core/는 게임/시뮬을 모름.
- 나중에 분리 필요 시(시뮬을 파이썬으로 재분리 / 게임 빌드에서 시뮬 제외 / 시뮬만 다른 공식 실험)
  모두 쉬움 — 단, core/를 순수하게 유지하는 전제 하에.

## 큰 그림

```
Phase 0 (S0 재정의)  →  M0  →  M1  →  M1.5  →  M2  →  M3  →  M4  →  M5
 core/ 구축+시뮬이식     스켈레톤  입력   UI/i18n  콘텐츠  반응형  정리   빌드
 +수치 freeze
```

의존성:
```
Phase0(core/+freeze) ─── 필수 선행 ───┐
                                      ▼
M0(스켈레톤) → M1(입력) → M1.5(UI/i18n) → M2(콘텐츠) → M3(반응형) → M4(정리) → M5(빌드)
```
- Phase 0가 M2의 전제(거목HP/파워업/룬/게임레벨 수치는 전부 core/에서).
- M1.5의 i18n 인프라는 먼저 깔아도 되나, 문자열 확정은 M2 이후 유리.

## Phase 0 — `core/` SSOT 구축 + 시뮬 이식 + 수치 freeze ⭐최우선

목표: 밸런스 계산식을 GDScript 순수 로직 한 곳에 세우고, 게임과 헤드리스 시뮬이 공유하게 만든다.
파이썬 시뮬 결과와 일치 검증(패리티) 후 수치 확정.

| # | 작업 | 산출물 | 완료 기준 |
|---|------|--------|-----------|
| 0-1 | 원본 baseline 수치 추출 | 조사 메모 | 원본 git에서 풀 HP/보상/재생, 무기 공격력, 스킬 비용, 월드 해금비용, 구 분노 게이지 값 확보 |
| 0-2 | `core/` 모듈 레이아웃 설계 | 디렉토리 스켈레톤 | 아래 core/ 구조 확정, 전부 RefCounted/정적, Node 의존 0 |
| 0-3 | 데이터 레이어 작성 | `core/data/*.gd` | 풀·무기·스킬·월드·파워업50·룬6·게임레벨 수치를 데이터 클래스로 |
| 0-4 | 계산 레이어 작성 | `core/stat_block.gd`, `economy.gd`, `progression.gd`, `rng.gd` | 파이썬 시뮬 공식(DPS/수입/처치율/세션곡선/게임레벨XP/씨앗게이트)을 GDScript로 이식 |
| 0-5 | 헤드리스 시뮬 러너 | `sim/run_sim.gd` | `godot --headless --script res://sim/run_sim.gd full` 실행, core/ 호출 |
| 0-6 | 패리티 검증 | 대조 리포트 | GDScript 시뮬 결과 ≈ 파이썬 결과(월드해금/초월/스킬맥스/게임레벨 오차 허용범위) |
| 0-7 | 수치 freeze | 커밋 | core/ 데이터 확정. 이후 단계는 이 수치 사용. balance_sim.py는 검증 도구로 보존 |

core/ 구조(안):
```
core/
  data/  grass.gd  weapons.gd  skills.gd  worlds.gd
         powerups.gd  runes.gd  game_level.gd
  stat_block.gd     # 공격력/공속/범위/이속/자석/코인가치/치명 벡터
  economy.gd        # 처치율·세션수입·거목DPS
  progression.gd    # 스킬비용·해금소요·세션레벨곡선·게임레벨XP·씨앗게이트
  rng.gd            # 시드 RNG(재현성)
sim/
  run_sim.gd        # 헤드리스 러너 + 시나리오
  balance_sim.py    # (검증용 보존)
```

> 미커밋 상태인 세션 레벨 곡선 작업(파이썬)은 0-4에서 core/로 이식하며 함께 확정.
