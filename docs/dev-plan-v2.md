# 풀죽이기 v2 — 세부 개발 계획 (실행 로드맵)

> 상태: 기획 확정(freeze 직전). 이 문서는 실제 구현 착수용 세부 실행 계획.
> 상위 기획·설계 확정 내용은 `docs/game-spec.md`, 밸런스 수치는 `sim/balance_sim.py`(→`core/`) 참조.
> 원본(이식 대상) 코드: `../game-kill_grass` 및 git `HEAD 4cd58ca`. **원본 실제 코드 기준으로 작성**(문서에만 있고 미구현인 것 제외).

## 전역 원칙 (에셋·UI·스타일)

- **그래픽·사운드·UI·레이아웃은 원본 게임 것을 그대로 이식.** 변경은 이 문서/`game-spec.md`에 **명시된 것만**.
- **텍스트 스타일·간격·폰트 등 스타일링도 원본 방식 유지.**
- UI 문구 원칙: 텍스트 지양, 아이콘/색상 우선, 원본에 없던 신규 문자열 금지(29개 언어 번역량 절감).
- **⚠️ 문서-코드 불일치 주의**: 원본 CLAUDE.md엔 `weapon_shop`·`pause_menu`·`info_panel`이 적혀 있으나 **실제 코드엔 없음**(미구현) → 이식 대상 아님. 무기 구매는 `upgrade_panel` 안, 일시정지는 ESC 나가기 다이얼로그(신규)가 대체.

## 아키텍처 결정 (확정)

**A안 — 공통 `core/` (SSOT).** 밸런스 수치·공식을 GDScript 순수 로직 레이어(`core/`) 한 곳에 두고,
**게임과 헤드리스 시뮬이 같은 코드를 호출**한다. 파이썬 `balance_sim.py`처럼 로직을 별도 복제하는 방식은 drift 위험이 있어 지양(game-spec §9.1).

- **핵심 규칙:** `core/`에는 화면/노드/입력 코드 금지 — 순수 함수만(Godot Node 의존 0).
- 관계: `게임 → core/ ← 시뮬` (단방향). core/는 게임/시뮬을 모름.
- 나중에 분리(시뮬 재분리 / 시뮬 제외 빌드) 쉬움 — core/를 순수하게 유지하는 전제 하에.
